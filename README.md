# Звіт до лабораторної роботи №8

**Тема:** React Fundamentals: компоненти, JSX, props, стан, події та списки.  
**Мета:** Ознайомитися з базовими принципами розробки застосунків на React. Навчитися створювати компоненти, передавати дані через props, керувати локальним станом за допомогою useState, обробляти події, відображати списки та використовувати умовний рендеринг.  
**Застосунок:** Study Planner (планувальник навчальних завдань).  
**Стек технологій:** React 19.3.1, TypeScript 5.8.2, Vite 8.3.5, SCSS (BEM), ESLint 10.14.0, Node.js 24.21.0.

---

## 1. Загальні відомості та реалізований функціонал

У ході виконання лабораторної роботи розроблено клієнтський застосунок Study Planner для управління списком навчальних завдань. Робота зі станом організована за допомогою хука `useState` з дотриманням принципу незмінності даних (immutable update).

Функціональні можливості застосунку:
1. Відображення списку завдань із зазначенням назви, опису, категорії, пріоритету (low, medium, high) та статусу виконання.
2. Додавання нового завдання з валідацією обов'язкового поля назви (повідомлення про помилку відображається в інтерфейсі без використання alert).
3. Перемикання статусу виконання завдання (виконано / в процесі) зі зміною візуального стилю.
4. Видалення окремого завдання зі списку.
5. Очищення всіх виконаних завдань зі списку.
6. Фільтрація списку за трьома режимами: всі завдання, невиконані, виконані.
7. Відображення кількості завдань безпосередньо на кнопках фільтрації.
8. Пошук завдань за назвою, описом або категорією.
9. Сортування завдань за рівнем пріоритету.
10. Підрахунок статистики в реальному часі (загальна кількість, виконані, невиконані, відсоток прогресу) без використання надлишкового стану.
11. Умовний рендеринг повідомлень для порожнього списку та для порожнього результату фільтрації.

Проєкт організовано за компонентним принципом:

```text
src/

│   ├── TaskForm.scss

│   ├── TaskStats.scss

│   ├── TaskFilters.scss
│   ├── TaskList.tsx         # Відображення списку завдань та умовний рендеринг
│   ├── TaskList.scss
│   ├── TaskItem.tsx         # Елемент окремого завдання
│   └── TaskItem.scss
├── types/
│   └── task.ts              # Типізація моделей Task, Priority, FilterType
├── data/
│   └── initialTasks.ts      # Початковий набір даних
├── styles/
│   └── _variables.scss      # Змінні стилів (кольори, розміри, шрифти)
├── App.tsx                  # Кореневий компонент, збереження стану та обробники подій
```

## 4. Відповіді на контрольні запитання

### 1. Що таке React-компонент і чому інтерфейс у React будується з компонентів?
React-компонент — це незалежна функція або клас, яка приймає вхідні параметри (props) і повертає опис елементів інтерфейсу у вигляді JSX. Інтерфейс будується з компонентів для забезпечення модульності, ізоляції стану та стилів, можливості повторного використання коду та спрощення тестування і підтримки.

### 2. Що таке JSX та чим JSX відрізняється від звичайного HTML?
JSX (JavaScript XML) — це розширення синтаксису JavaScript, що дозволяє описувати DOM-структуру всередині JavaScript-коду. На етапі збірки JSX перетворюється на виклики `React.createElement` або функції jsx-runtime.  
Основні відмінності від HTML:
- Імена властивостей записуються в нотації camelCase (наприклад, `className`, `htmlFor`, `onClick`).
- Усі теги обов'язково повинні бути закритими.
- Всередині фігурних дужок `{}` можна передавати JavaScript-вирази.

### 3. Чому JSX повинен повертати один кореневий елемент або Fragment?
JSX є синтаксичним еквівалентом виклику функції. Функція в JavaScript не може повертати кілька окремих значень без обгортки в структуру даних. Єдиний кореневий елемент або `Fragment` (`<></>`) дозволяє згрупувати список дочірніх вузлів без додавання зайвих елементів до реального DOM-дерева.

### 4. Як у JSX вставляється JavaScript-вираз?
JavaScript-вираз вставляється за допомогою одинарних фігурних дужок `{}`. Усередині дужок можна обчислювати змінні, виконувати арифметичні операції, викликати методи масивів (`map`, `filter`), застосовувати тернарні оператори та шаблонні рядки.

### 5. Що таке props? Як вони передаються від батьківського компонента до дочірнього?
Props (properties) — це параметри тільки для читання, які передаються від батьківського компонента до дочірнього через атрибути JSX-тегу. У дочірньому функціональному компоненті props доступні як аргумент функції. Props реалізують односпрямований потік даних (зверху вниз).

### 6. Чи може дочірній компонент напряму змінювати props? Як правильно передати callback для зміни даних?
Дочірній компонент не може змінювати отримані props напряму, оскільки вони є незмінними (read-only). Для зміни даних батьківський компонент передає в дочірній функцію зворотного виклику (callback) через props, а дочірній компонент викликає цю функцію при виникненні події (наприклад, кліку).

### 7. Для чого використовується useState? Що повертає цей hook?
Хук `useState` призначений для створення та збереження локального стану у функціональному компоненті між циклами рендерингу. Він повертає масив із двох елементів: поточне значення стану та функцію для його оновлення (`[state, setState]`).

### 8. Чому не слід напряму змінювати масив або об’єкт, який зберігається у state?
React порівнює попередній і наступний стан за посиланням на об'єкт (поверхневе порівняння, `Object.is`). При прямій мутації об'єкта чи масиву посилання в пам'яті не змінюється, тому React не ініціює повторний рендеринг компонента, а інтерфейс не оновлюється.

### 9. У чому різниця між setState(value) та setState(prev => ...)?
`setState(value)` встановлює нове значення безпосередньо. У випадках пакетної обробки (batching) це значення може базуватися на застарілому стані.  
Форма `setState(prev => ...)` приймає функцію оновлення, яка гарантовано отримує найактуальніший стан на момент виконання. Це необхідно при послідовних оновленнях стану або при роботі з масивами й об'єктами.

### 10. Як React рендерить список елементів через map?
Метод `map()` ітерує масив даних і для кожного елемента повертає JSX-елемент. React інтерпретує отриманий масив віртуальних вузлів і послідовно вставляє їх у дерево DOM.

### 11. Для чого потрібен prop key у списку? Чому використання індексу масиву як key може бути проблемним?
Проп `key` надає кожному елементу списку унікальний стабільний ідентифікатор, який алгоритм примирення (Reconciliation) використовує для визначення того, які елементи були змінені, додані чи видалені.  
Використання індексу масиву як `key` є небажаним при зміні порядку, видаленні або додаванні елементів, оскільки індекси зміщуються. Це призводить до помилок збереження внутрішнього стану некерованих елементів форми та зниження продуктивності.

### 12. Що таке умовний рендеринг у React? Назвіть декілька способів його реалізації.
Умовний рендеринг — це механізм відображення елементів інтерфейсу залежно від стану чи умов.  
Способи реалізації:
1. Конструкція `if/else` з раннім поверненням (early return).
2. Тернарний оператор (`умова ? <Вузол1 /> : <Вузол2 />`).
3. Логічний оператор `&&` (`умова && <Вузол />`).
4. Конструкція `switch/case` або словники функцій/компонентів.

### 13. Чим відрізняється локальний state компонента від props?
- `state` створюється, контролюється та змінюється всередині самого компонента за допомогою `useState`.
- `props` передаються компоненту ззовні від батьківського компонента і є незмінними для отримувача.

### 14. Де доцільно зберігати state, який використовується кількома дочірніми компонентами?
Такий стан піднімають до найближчого спільного батьківського компонента (патерн Lifting State Up). Батьківський компонент зберігає стан у `useState` і передає поточні дані вниз через props, а функції модифікації — через callbacks.

### 15. Що відбудеться після виклику setter-функції, яку повертає useState?
1. React планує оновлення значення стану.
2. Компонент ставиться в чергу на повторний рендеринг.
3. Функція компонента виконується з новим значенням стану.
4. Порівнюється новий Virtual DOM із попереднім (Diffing) і вносяться точкові зміни в реальний DOM.

### 16. Чому статистику кількості виконаних завдань не обов’язково зберігати в окремому state?
Кількість виконаних завдань є похідним значенням (derived state). Її можна швидко і точно обчислити безпосередньо під час рендерингу на основі масиву завдань за допомогою методів `.length` та `.filter()`. Зберігання таких даних в окремому стані призводить до надлишковості та ризику розсинхронізації.

### 17. Що означає immutable update і як він застосовується до масивів у React?
Immutable update означає оновлення структури даних без модифікації існуючого екземпляра — замість мутації створюється нова копія з внесеними змінами.  
Застосування до масивів:
- Додавання: `[newTask, ...prevTasks]` замість `.push()`.
- Видалення: `prevTasks.filter(item => item.id !== id)` замість `.splice()`.
- Оновлення: `prevTasks.map(item => item.id === id ? { ...item, completed: !item.completed } : item)`.

## 5. Порядок демонстрації на захисті

1. Демонстрація додавання завдання: введення назви, вибір параметрів, валідація при порожньому полі назви без використання alert.
2. Демонстрація зміни стану: перемикання статусу завдання (виконано / в процесі), оновлення відсотка прогресу, видалення завдання.
3. Демонстрація фільтрації та пошуку: фільтрація за статусом, робота лічильників, умовний рендеринг повідомлення при відсутності результатів.
4. Аналіз вихідного коду: демонстрація файлу `App.tsx` (використання `useState`, immutable updates), компонентів `TaskForm.tsx`, `TaskList.tsx` (`map`, `key`), типів у `task.ts` та результатів лінтера (`npm run lint`).
