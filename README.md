## 📌 Опис проєкту

**Study Planner** — це навчальний клієнтський застосунок, розроблений для планування та відстеження виконання навчальних завдань. Уся робота зі станом реалізована за допомогою стандартного React-хука `useState` з дотриманням принципу незмінності даних (immutability).

### 🚀 Реалізований функціонал:
1. **Відображення списку навчальних завдань:** назва, опис, категорія, кольоровий бейдж пріоритету (`low`, `medium`, `high`), статус виконання.
2. **Додавання нового завдання:** валідація обов'язкового поля назви (без виклику `alert`, з відображенням помилки в інтерфейсі), вибір пріоритету та категорії, автоматичне очищення форми після успішного додавання.
3. **Керування станом завдань:**
   - Позначення завдання як виконаного / повернення до статусу «не виконано».
   - Видалення завдання зі списку.
   - Очищення всіх виконаних завдань в один клік.
4. **Фільтрація та сортування:**
   - Фільтри: «Всі», «Не виконані», «Виконані» з динамічними лічильниками на кнопках.
   - Пошук за назвою, описом або категорією.
   - Сортування за пріоритетом (High → Low, Low → High).
5. **Статистика в реальному часі:**
   - Загальна кількість завдань, кількість активних та виконаних.
   - Візуальний прогрес-бар виконання плану (відсоток обчислюється динамічно без зайвого state).
6. **Умовний рендеринг (Conditional Rendering):**
   - Спеціальний екран «Завдань поки немає. Додайте перше навчальне завдання.», якщо список порожній.
   - Окреме повідомлення «За цим фільтром завдань немає.», якщо нічого не знайдено за поточним фільтром чи пошуком.
   - Візуальне перекреслення та зміна стилів для завершених завдань.

## 🎓 Відповіді на контрольні запитання до захисту

### 1. Що таке React-компонент і чому інтерфейс у React будується з компонентів?
**Відповідь:** React-компонент — це незалежна, перевикористовувана функція (або клас), яка приймає вхідні дані (`props`) і повертає опис інтерфейсу у вигляді JSX. Компонентний підхід забезпечує модульність, полегшує тестування, повторне використання коду, ізоляцію стилів/логіки та спрощує підтримку масштабованих додатків.

### 2. Що таке JSX та чим JSX відрізняється від звичайного HTML?
**Відповідь:** JSX (JavaScript XML) — це синтаксичне розширення JavaScript, яке дозволяє писати розмітку, візуально схожу на HTML, прямо всередині JS/TS файлів. Під час збірки JSX транспілюється у виклики функцій React (`React.createElement` або jsx-runtime).  
Відмінності від HTML:
- Атрибути пишуться в camelCase (наприклад, `className` замість `class`, `htmlFor` замість `for`, `onClick` замість `onclick`).
- Усі теги обов'язково повинні закриватися (наприклад, `<input />`, `<br />`).
- У фігурних дужках `{}` можна передавати будь-які валідні JavaScript-вирази.

### 3. Чому JSX повинен повертати один кореневий елемент або Fragment?
**Відповідь:** JSX є синтаксичним цукром над викликом функцій. Функція в JavaScript не може повернути два значення одночасно без обгортання в об'єкт або масив. Кореневий елемент або фрагмент (`<></>` чи `<React.Fragment>`) дозволяє перетворити декілька дочірніх вузлів в єдине дерево без додавання зайвих DOM-вузлів.

### 4. Як у JSX вставляється JavaScript-вираз?
**Відповідь:** За допомогою фігурних дужок `{}`. Усередині дужок можна обчислювати змінні, викликати методи (`tasks.map(...)`), використовувати тернарні оператори (`condition ? a : b`), шаблонні рядки тощо.

### 5. Що таке props? Як вони передаються від батьківського компонента до дочірнього?
**Відповідь:** `props` (properties) — це вхідні дані, які передаються від батьківського компонента до дочірнього як атрибути тегу (наприклад, `<TaskItem task={item} onToggle={handleToggle} />`). У дочірньому компоненті вони доступні як об'єкт аргументу функції. `props` є незмінними (read-only) для дочірнього компонента (односпрямований потік даних — unidirectional data flow).

### 6. Чи може дочірній компонент напряму змінювати props? Як правильно передати callback для зміни даних?
**Відповідь:** Ні, дочірній компонент ніколи не повинен змінювати свої `props` напряму (це порушує чисту архітектуру React). Для зміни даних батьківський компонент передає в дочірній функцію зворотного виклику (callback), наприклад `onToggle={(id) => handleToggle(id)}`, яку дочірній компонент викликає при настанні події.

### 7. Для чого використовується useState? Що повертає цей hook?
**Відповідь:** `useState` використовується для збереження та керування внутрішнім станом функціонального компонента між рендерами. Він повертає масив із двох елементів: `[currentValue, setValue]` — поточне значення стану та функцію-сеттер для його оновлення.

### 8. Чому не слід напряму змінювати масив або об’єкт, який зберігається у state?
**Відповідь:** React перевіряє необхідність повторного рендерингу (re-render) за посиланням на об'єкт (shallow comparison / `Object.is`). Якщо мутувати масив напряму (наприклад, `tasks.push(...)` або `task.completed = true`), посилання на об'єкт не зміниться, React не зафіксує змін і інтерфейс не оновиться. Крім того, пряма мутація ламає передбачуваність стану.

### 9. У чому різниця між setState(value) та setState(prev => …)?
**Відповідь:** 
- `setState(value)` встановлює нове значення безпосередньо. Якщо кілька оновлень відбуваються послідовно (batching), `value` може базуватися на застарілому значенні стану (stale state).
- `setState(prev => ...)` приймає функцію-оновлювач, яка гарантовано отримує найактуальніший стан на момент виконання виклику. Це критично при роботі з масивами, лічильниками чи асинхронними подіями.

### 10. Як React рендерить список елементів через map?
**Відповідь:** Метод масиву `.map()` трансформує кожен елемент масиву даних у відповідний JSX-вузол:  
`{tasks.map(task => <TaskItem key={task.id} task={task} />)}`.  
React вставляє утворений масив віртуальних DOM-елементів у дерево.

### 11. Для чого потрібен prop key у списку? Чому використання індексу масиву як key може бути проблемним?
**Відповідь:** `key` — це унікальний ідентифікатор, за допомогою якого алгоритм примирення (Reconciliation) React зіставляє елементи списку між рендерами, розуміючи, який елемент було додано, видалено чи переміщено.  
Використання індексу як `key` є проблемним, тому що при видаленні або додаванні елементів (особливо на початку списку) індекси всіх наступних елементів зміщуються. Це призводить до помилок збереження внутрішнього стану інпутів, некоректних анімацій та падіння продуктивності. `key` повинен бути стабільним (наприклад, унікальний `task.id`).

### 12. Що таке умовний рендеринг у React? Назвіть декілька способів його реалізації.
**Відповідь:** Умовний рендеринг — це відображення різних елементів інтерфейсу залежно від виконання певних умов або значень стану.  
Способи:
1. Раннє повернення (Early return): `if (!hasTasks) return <EmptyState />;`
2. Тернарний оператор: `{isCompleted ? <BadgeDone /> : <BadgePending />}`
3. Логічне «І» (`&&`): `{error && <p className="error">{error}</p>}`
4. Конструкції `switch/case` або словники об'єктів для відображення відповідного UI.

### 13. Чим відрізняється локальний state компонента від props?
**Відповідь:**
- `state` — внутрішня пам'ять компонента, створюється та змінюється всередині самого компонента (`useState`).
- `props` — зовнішні вхідні дані, передаються від батьківського компонента до дочірнього і є незмінними (read-only) для отримувача.

### 14. Де доцільно зберігати state, який використовується кількома дочірніми компонентами?
**Відповідь:** Такий стан піднімають до їхнього найближчого спільного предка (техніка "Lifting State Up"). Спільний батьківський компонент зберігає `state` і передає його дочірнім через `props`, а зміни вносить через передані callback-функції.

### 15. Що відбудеться після виклику setter-функції, яку повертає useState?
**Відповідь:** 
1. React планує оновлення стану та ставить компонент у чергу на перерендер.
2. Під час наступного циклу рендерингу компонент виконується знову з новим значенням стану.
3. React порівнює новий Virtual DOM зі старим (Diffing) і вносить мінімально необхідні зміни в реальний DOM.

### 16. Чому статистику кількості виконаних завдань не обов’язково зберігати в окремому state?
**Відповідь:** Тому що це надлишковий (derived) стан. Загальна кількість, кількість виконаних та відсоток прогресу можуть бути миттєво обчислені з уже наявного масиву `tasks` під час рендерингу (за допомогою `tasks.length` та `filter()`). Зберігання обчислюваних значень в окремому `state` ускладнює код, потребує синхронізації та призводить до багів розсинхронізації даних.

### 17. Що означає immutable update і як він застосовується до масивів у React?
**Відповідь:** Immutable update означає оновлення даних шляхом створення копії без зміни (мутації) початкового об'єкта або масиву.  
Для масивів у React:
- Додавання: `[...prevTasks, newTask]` або `[newTask, ...prevTasks]` замість `tasks.push(newTask)`.
- Видалення: `prevTasks.filter(task => task.id !== targetId)` замість `tasks.splice(...)`.
- Оновлення елемента: `prevTasks.map(t => t.id === targetId ? { ...t, completed: !t.completed } : t)`.
